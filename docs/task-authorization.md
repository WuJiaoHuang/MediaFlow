# Stage 3 权限矩阵与实现约定

设计先于改造明确；Stage 2 旧素材迁移默认 LIBRARY，不自动私有化。

| 对象 / 入口 | ADMIN | 当前 EDITOR 执行人 | 当前 REVIEWER 审核人 | 上传者 | 无关登录用户 |
| --- | --- | --- | --- | --- | --- |
| 任务及任务素材 / 操作历史 | 全部 | 仅当前分配 | 仅当前指定 | 没有额外任务权限 | 404 |
| ACTIVE + LIBRARY 媒体库入口 | 可读 | 可读 | 可读 | 可读 | 可读 |
| ACTIVE + RESTRICTED 媒体库入口 | 可读 | 有关联任务时可读 | 有关联任务时可读 | 可读 | 404 |
| ARCHIVED 素材 | 可读 | 不可读 | 不可读 | 非 ADMIN 不可读 | 不可读 |
| 任务上下文内的文件 / Cookie / 续签 | 任务存在且关联素材 | 当前任务授权 + 当前关联 | 当前任务授权 + 当前关联 | 单独上传者身份不能代替任务授权 | 404 |

多角色可读范围为有效授权并集；失去对应角色后即使任务仍保存其 ID，也没有该角色任务授权。已有账号禁用继续由认证过滤器拦截。

共享素材允许独立媒体库访问，这是基础授权，不宣称为私有。重新分配后旧执行人不能访问原任务及其上下文凭据；若其仍有共享 / 上传者 / 其他任务带来的独立素材授权，媒体库入口仍按该授权可读。RESTRICTED 素材用于要求私有隔离的情况；仅 ADMIN 可切换 accessScope，改变计入原媒体字段审计并检查 version。

统一 AuthorizationService 实现对象权限，SQL 使用相同主体参数与 EXISTS 关联条件。列表、统计、修改日志、详情、文件和凭据续签均受限制。任务上下文必须先通过任务授权，即使素材共享也不能跳过。

预览凭据有 asset 和可选 task claim。Cookie 名区分任务上下文；URL 只携带 taskId 标识，不放 Token。凭据不能换到另一上下文；每次请求仍查询数据库授权，不把 120 秒有效期当作授权缓存。

任务状态：PENDING → PROCESSING → REVIEWING → COMPLETED；REVIEWING 可带必填原因退回 PROCESSING。执行动作仅当前 EDITOR 执行人或 ADMIN，审核动作仅当前 REVIEWER 审核人或 ADMIN。ADMIN 的代办仍遵循相同状态 / version，不能任意跳状态；COMPLETED 不可编辑或重开。

分配调整保持任务当前状态，立刻影响读取权限，不删除历史。任务和日志同事务，行锁 + version + 带旧 version 的 UPDATE 保证并发只成功一次。任务列表在数据库过滤授权，不先全量加载。操作人只取认证身份。

拒绝策略：创建 / 管理编辑 / 人员选择属于 ADMIN 专属功能，普通用户不论 taskId 是否存在均为 403，不查询任务存在性；详情、任务素材、历史与状态动作先按任务数据授权，无关联则 404；列表只返回已授权行，无匹配时返回 200 空页；有任务读权限但不是该动作执行角色则 403。历史共享归档素材保留 Stage 2 的 403 行为，受限素材和无授权任务上下文使用 404。
