## 实际运行环境

复用 Java 17.0.12、Maven 3.9.10、Node.js 22.17.1、本机 MySQL 8.0.41。后端 8280，前端 5280，通过 Vite 同源代理访问。原本默认 8080 / 5173 配置不变；采用独立端口避免干扰此前实例。

后端启动（根目录，当前本地 .env 未设置 SERVER_PORT 时可用进程变量覆盖）：

```powershell
$env:SERVER_PORT='8280'
$env:STORAGE_ROOT=Join-Path (Get-Location).Path '.local/media-storage'
powershell -ExecutionPolicy Bypass -File scripts/start-backend.ps1
```

前端启动（另一终端）：

```powershell
cd frontend
$env:MEDIAFLOW_BACKEND_URL='http://127.0.0.1:8280'
npm run dev -- --port 5280
```

迁移脚本 sql/migrations/V002__media_management.sql 通过 mysql 客户端执行，应用不自动改表。数据库初始化与配置详见 README。

## 调试中发现并解决的问题

- 初次 H2 迁移去除 MySQL 索引时留下语法片段，修正测试 DDL；真实 MySQL 原迁移未重建表。
- Tika 将 WebM 识别为 Matroska、ISO MP4 识别为 QuickTime；补容器头白名单校验，保持内容与声明一致，拒绝真正 QuickTime 改名。
- 超长数字素材 ID 不再触发预览过滤器 500，保持未认证并返回 401，新增回归测试通过。
- 预览 claim 的泛型调用匹配了 String.valueOf(char[]) 导致类型错误，明确按 Object 转字符串并通过限定凭据测试。
- MyBatis 默认忽略 NULL 会让取消分类 / 移回根分类失效，两个可空外键显式配置 ALWAYS 更新策略。
- CREATE_NEW 失败清理逻辑可能误删 UUID 碰撞的旧文件，调整为只清理本次成功创建的文件并补充碰撞测试。
- Vite 首次按需依赖优化导致整页刷新，已将 resolver 注入的样式入口列入预构建；--force 冷启动后 7 项通过。
- Element Plus 选择器内部只读 input 被占位层遮挡；浏览器测试改为点击可见选择器容器，真实上传与编辑成功，没有绕过业务页面或用静态数据替代。

## 已知问题与明确边界

- 正常素材暂对全部登录角色可读，这不是最终任务级隔离；EDITOR 写入仍校验所有权，归档仅 ADMIN 可读。
- 预览凭据在退出后最多有效 120 秒；禁用用户 / 归档会拒绝后续请求，已下载或缓冲的数据不能收回。
- 内容嗅探不是完整解码、病毒扫描或转码，编码不被浏览器支持或媒体本身损坏时显示预览错误。
- 进程异常终止或清理 IO 失败可能留下孤立存储对象，需人工对照 media_file 对账；正常写入 / 数据库回滚路径已验证清理。
- 分类为全局唯一名称、最多两级、精确分类过滤，不做子树合计；大规模 / 更复杂目录结构需另行演进。
